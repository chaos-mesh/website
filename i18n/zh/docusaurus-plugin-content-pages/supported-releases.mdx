## 命名方案

我们的命名方案大体遵循 [语义化版本 2.0.0](https://semver.org/lang/zh-CN/)，并在 git 标签和 docker 镜像中加入 `v` 前缀：

```plain
v<major>.<minor>.<patch>
```

其中，每次发布都会增加 `<minor>`，而 `<patch>` 统计当前 `<minor>` 版本发布的补丁数量。补丁通常是相对于 `<minor>` 版本的一个小改动。

## 支持策略

我们的支持窗口涵盖**最新发布的两个版本**。鉴于我们大约**每六个月**发布一个新版最终版本，每个发布分支通常会得到大约一年的支持。

为此，我们提供以下两种类型的支持：

- [社区技术支持](#社区技术支持)
- [安全和 bug 修复](#安全和-bug-修复)

### 社区技术支持

你可以通过 CNCF Slack（[#project-chaos-mesh](https://cloud-native.slack.com/archives/C0193VAV272) 频道）或 [GitHub Discussions](https://github.com/chaos-mesh/chaos-mesh/discussions) 向社区寻求支持。

### 安全和 bug 修复

安全问题会尽快修复。它们会被回移植到最后两个版本，并立即为它们创建新的补丁版本。

如需增强功能或 bug 修复，我们会根据需要制作新的补丁版本。

## 我们如何确定支持的 Kubernetes 版本

通过 E2E 测试对不同版本的 Kubernetes 集群的兼容性进行测试后，Chaos Mesh 团队会基于其测试结果来确定 [Chaos Mesh 的支持状况](#chaos-mesh-的支持状况)。

以下是各版本的 E2E 测试所涉及的 Kubernetes 版本：

| 版本   | 测试的 Kubernetes 版本   |
| :----- | :---------------------- |
| master | 1.33.9, 1.34.5, 1.35.2 |
| 2.8    | 1.33.9, 1.34.5, 1.35.2 |
| 2.7    | 1.26.13, 1.27.10, 1.28.6 |
| 2.6    | 1.20.15, 1.23.4, 1.25.1 |
